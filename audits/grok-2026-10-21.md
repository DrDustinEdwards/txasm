## Threat model (STRIDE)

Spoofing: magic-link only, password login disabled, sessions in KV. Admin is an email allowlist applied on first account creation.

Tampering: D1 has no row-level security. Writes go through `getDataAccess`. A chair can store a sponsor URL that the public program page places in `href` (TX-2). Rich text is an allowlist.

Repudiation: role grants store `grantedById`. Backup runs log a run id. Payment state cannot change, because the PayPal methods throw (TX-9).

Information disclosure: dormant email logs the full sign-in URL (TX-5). `/health` returns backup age to anyone (TX-6). Published documents and accepted abstracts in a public-stage edition are meant to be public.

Denial of service: the sign-in form does not hit Better Auth's limiter (TX-4). A chair publish holds a Browser Rendering session for up to 90 seconds. Public search scans `abstract` and stops at 500 rows.

Elevation: missing frame denial on HTML (TX-1) would let a same-origin iframe submit an admin form once this worker is the host. PDF.js 6.1.200 is inside an advisory for script execution on a malicious PDF (TX-3). A chair is not a platform admin, and `roles.grant` refuses the admin role.

## Findings

### TX-1 MAJOR, security, high confidence

`app/entry.server.tsx` line 37 sets `Content-Type` and leaves the other response headers untouched. The arranged-book preview (`app/routes/admin.editions.$editionId.book.preview.tsx` lines 20 to 22) returns a full HTML document the same way. Session cookies from the installed Better Auth are `httpOnly` and `sameSite: "lax"` (`better-auth/dist/cookies/index.mjs` lines 32 to 35), and this repo does not override them. A same-origin iframe still sends that cookie, so a framed admin page can submit a role grant, a document delete, or a book publish.

`app/lib/paged.ts` line 5 inserts `https://unpkg.com/pagedjs@0.4.3/dist/paged.polyfill.js` with no integrity attribute. The preview is served on the app origin to a chair, so that script runs with the chair's cookie. The PDF renderer loads the same URL inside Browser Rendering (`app/lib/book-pdf.server.ts` lines 42 to 57).

Image document responses do set `X-Content-Type-Options: nosniff` and `Content-Security-Policy: default-src 'none'; style-src 'unsafe-inline'; sandbox` (`app/lib/serve-document.server.ts` lines 71 to 76). PDFs and HTML do not.

`https://txasm.org/` is still WordPress (Apache and nginx, Divi, generator WordPress 7.1.3). `https://txasm.org/health` is a WordPress 404. This worker is not that host today, so the iframe is not exploitable on the public name yet. `npm run deploy` ships the worker that has the gap. `CLAUDE.md` line 26 says DNS stays put until cutover.

Smallest fix: on both HTML responses, call `applyHeaderSet` with `buildSecurityHeaders()` from `@dustinedwards/site-runtime/headers` (already installed at v0.7.0). That set includes `frame-ancestors 'none'` and `X-Frame-Options: deny`. Self-host `paged.polyfill.js` the way `public/pdfjs` is vendored. The shell loads Inter from `fonts.googleapis.com` (`app/root.tsx` lines 22 to 31), so the policy needs an override with a written reason, or the shell should use the woff2 files already under `public/fonts`. Do not pass an `extraDirectives` option. This repo never calls that API.

### TX-2 MAJOR, security, high confidence

Sponsor URLs are stored trimmed and otherwise unchecked (`app/lib/data-access/speakers-sponsors.ts` lines 196 and 217). The comment on lines 172 to 173 says the fields are escaped at render time. The public program renders `href={sponsor.url}` (`app/routes/meetings.$slug.program.tsx` lines 257 to 264). React escapes quotes in the attribute. It does not reject a `javascript:` scheme. A click runs the script on this origin, including for an admin who opens the program.

`getPublicProgram` returns those sponsors when the edition status is `scheduled`, `complete`, or `archived` (`app/lib/data-access/program.ts` lines 137 to 151). The writer is a chair of that edition, or a platform admin. `settings.update` already refuses a Facebook URL that does not start with `http://` or `https://` (`app/lib/data-access/settings.ts` lines 167 to 172). Footer links are checked at render time (`app/routes/public.layout.tsx` lines 255 to 267). Sponsors are the path that skips the check.

Smallest fix: the same `^https?://` test on sponsor create and update, and drop any stored value that fails it.

### TX-3 MAJOR, security, high confidence

The in-browser viewer loads `/pdfjs/pdf.min.mjs` and `/pdfjs/pdf.worker.min.mjs` (`app/components/pdf-viewer.tsx` lines 17 to 18). The vendored file says `pdfjsVersion = 6.1.200` (`public/pdfjs/pdf.min.mjs` line 23). The lockfile's `pdfjs-dist` is the same range (`^6.1.200`) and is a type import only, so the browser never loads the package.

`npm audit` reports GHSA-hq66-cqwq-w95j on `pdfjs-dist` versions at or above 5.6.83 and below 6.2.108: arbitrary JavaScript execution when a malicious PDF is opened. Published documents are public, and this component is what opens them. A malicious PDF was not built for this audit. The version and the load path were.

Smallest fix: replace the vendored `pdf.min.mjs`, `pdf.worker.min.mjs`, and the matching wasm with 6.2.108 or newer, and move the lockfile with them. `npm audit fix` can move the package. It does not replace `public/pdfjs`.

### TX-4 MAJOR, security, high confidence

`app/routes/signin.tsx` line 32 calls `getAuth(env).api.signInMagicLink`. That direct call goes through `dispatchAuthEndpoint`, which does not call `onRequestRateLimit`. The HTTP handler does (`better-auth/dist/api/index.mjs` lines 163 to 169), and `app/routes/api.auth.$.ts` is the route that uses the handler.

With `secondaryStorage` set, the library stores the counter in that store (here, KV) rather than in isolate memory (`create-context.mjs` lines 169 to 174). The limiter is enabled when `NODE_ENV` is `production`. The magic-link plugin adds a rule of 5 requests per 60 seconds on `/sign-in/magic-link` and `/magic-link/verify` (`magic-link/index.mjs` lines 157 to 162). The form never enters that rule.

`EMAIL_ENABLED` is `"false"` and the send binding is commented out, so today the call writes a verification row and, via TX-5, a sign-in URL into logs. The same function sends mail once email is turned on. No Turnstile widget is present. A live sign-in was not submitted.

Smallest fix: send the form through `auth.handler`, or invoke the same limiter before `signInMagicLink`. Keep the magic-link rule, and add a per-address cap that survives a new isolate.

## What this repo does well

The data-access layer is the boundary, and eslint enforces it. Roles fail closed, admin is not grantable from the role screen, and a chair check takes the edition id. Rich text is a small allowlist that drops attributes. The nightly backup excludes the token tables, checks row counts, throws when the cron fails, and the exclusion test goes red when `verification` is removed from the list. CI pins its actions and sets `contents: read`. Uploads check MIME and size before the R2 write, and the object key is built on the server. Image responses are sandboxed. Public search is parameterized and limited to accepted abstracts in a public-stage edition. The lockfile pins d1-dump v0.5.0 and site-runtime v0.7.0 at the tagged commits, and the backup call does not pass `pageRows`.
