## Per item

**1. compatibility_date, nodejs_compat, observability, structured logs.** compatibility_date 2026-06-21 and nodejs_compat are set. Observability is fixed above. Logs are free-form strings (`console.log("[cron] tick ...")`, `console.error("[auth] ...")`, 9 sites in app/ and workers/). Vendor: structured JSON logs let Workers Logs filter by field. Recommendation: convert in a follow-up; low risk, but it touches every log site, so it is left out of this PR. The dormant-email path logs the magic link URL, which is a live sign-in credential; acceptable only while EMAIL_ENABLED is off.

**2. Env types from `wrangler types`.** Binding types are generated (worker-configuration.d.ts, gitignored, regenerated by postinstall and typecheck). The secrets (BETTER_AUTH_SECRET, BETTER_AUTH_URL, ADMIN_EMAIL, ADMIN_EMAILS) are hand-declared in app/env.d.ts because they are dashboard secrets. Not verified: whether the pinned wrangler can generate secret types from a `.dev.vars.example`. Also, wrangler.jsonc's comment still names RESEND_API_KEY, STRIPE_SECRET_KEY and STRIPE_WEBHOOK_SECRET, which no code uses (CLAUDE.md says PayPal and Cloudflare Email). Stale comment only; fix it when the PayPal work lands.

**3. Constant-time compares.** There is no hand-written compare loop and no `timingSafeEqual` use. The only security comparisons are inside Better Auth. The PayPal webhook is not implemented yet (data-access.ts has `markPaidFromWebhook`; no route calls it). When it lands it is a money path: DECIDE 2.

**4. Promise rules.** Done above. `waitUntil` is never used (the only hit is a puppeteer option), `passThroughOnException` is not used, and the only module global is `getAuth`'s WeakMap keyed on env (an isolate cache of config, not request state). Clean.

**5. Bindings, not REST.** Everything goes through D1, R2, KV and Browser Rendering bindings. One deviation to record: app/lib/auth.server.ts imports `env` from `cloudflare:workers` (ambient) while CLAUDE.md says to use the injected context. Works and is vendor-sanctioned; recorded, not changed.

**6. Forms and email.** The only public form that triggers outbound work is /signin, which sends a magic link to any address. There is no Turnstile and no rate limit, so anyone can make the site send mail to arbitrary addresses once email is on. Turnstile needs a sitekey and secret from Dustin: DECIDE 3. Email already uses the native send_email binding, not a hand-rolled mailer; it is dormant until cutover and nothing was added.

**7. Hand-written auth, signing, payments, retries, API clients.** Auth is Better Auth (a library). There is no retry/backoff code and no third-party API client. Payments are not built: DECIDE 2.

**8. Markdown, feeds, sitemaps, charts, calendars.** app/lib/richtext.ts (137 lines) is a small allowlist tokenizer for abstract text, deliberately dependency-free and security relevant. It is not Markdown, so Prelum and Enarratio do not apply. No feed, sitemap or chart code found. Nothing to replace.

**9. Rate limiting.** None anywhere. Better Auth has a built-in limiter, but with no `rateLimit` option set it uses in-memory storage, which does not hold across isolates. Options: the Workers Rate Limiting binding on /signin, a WAF rate-limit rule, or Better Auth's `rateLimit.storage: "secondary-storage"` (already wired to KV). DECIDE 3.

**10. Static Assets, shared packages.** The Worker serves assets through @cloudflare/vite-plugin (Workers Static Assets, not Pages). None of Capsomer, security-headers, rate-limit or site-helpers is a dependency, and no local copies exist. No security headers are set anywhere (a grep for Content-Security-Policy and X-Frame-Options found nothing). Recommendation: adopt security-headers after reading its README: DECIDE 4.

## DECIDE points

1. **Add CI.** There is no .github directory, so lint, typecheck and `npm test` run only on a developer machine. Recommendation: yes, one workflow on pull requests only (private-repo minutes are limited) running `npm ci`, typecheck, lint, test. Needs your yes because it adds a workflow file and spends minutes.
2. **PayPal webhook, when built.** Money path. Recommendation: verify with PayPal's own verify-webhook-signature endpoint (or its SDK) rather than hand-rolling certificate checks, compare any shared values with `crypto.subtle.timingSafeEqual` over SHA-256 digests, and keep it as its own audited path per CLAUDE.md rule 4. Decide before that job starts.
3. **Sign-in abuse protection.** Recommendation: Turnstile on /signin plus the Workers Rate Limiting binding keyed on IP, before EMAIL_ENABLED goes true. Your steps: create a Turnstile widget in the Cloudflare dashboard, then `wrangler secret put TURNSTILE_SECRET_KEY`. This matters more because the magic link stays for non-admin users (see the PR for job_f0d60ee9a9f8).
4. **Adopt security-headers.** Recommendation: yes, after reading its README, in its own PR.
